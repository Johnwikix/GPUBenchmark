# Decisions

- 2026-10-20: Greenfield workspace; only the provided plan existed. No AGENTS.md was found in the project or existing G: ancestor directories. Plan fully read; v1.1 now defers FP4 at user request, including CLI, reference formats and acceptance. `--dtype fp4` is a configuration error, not a hardware capability statement.
- Protocol v1 was frozen before parallel CUDA/HIP/SYCL work. Backend objects remain inside independent worker processes. The host is MSVC C++20; GPU compiler settings are isolated. stdout is JSONL; stderr and library logs have separate paths; Windows Job Objects kill abandoned children.
- Vendor-independent host code uses vendored nlohmann/json3.11.3 and Khronos OpenCL-Headers v2024.10.24, with content SHA256 in the lock. OpenCL1.2 APIs load the existing System32 loader dynamically; no driver DLL is copied. Headers identify the source version, not an ICD support guarantee.
- Initial CUDA11.8 and MSVC19.51 could not form a supported Blackwell combination. NVIDIA's archived CUDA13.2 Windows documentation explicitly supports MSVC195x. Acquired fixed CUDA13.2.2 redist components, nvcc13.2.86/cuBLAS13.4.1.3; verified SHA256 against the official manifest. User-selected tool directory is G:\Tool\Cuda\13.2.2. No system Toolkit/driver replacement was performed. Original failed discovery/build evidence is retained.
- Sandbox MSVC compiler smoke failed C1902 in PDB services; the identical native build succeeded using normal machine permissions. We did not override compiler checks or treat the failed smoke as success.
- AMD has no SDK or GPU on this machine. Source uses an MSVC control process with HIP object and separately compiled per-gfx WMMA objects, and explicitly loaded optional BLAS. Intel has no matched oneAPI/oneMKL/UR or Intel GPU. Both are source-only, with failed prerequisite build commands retained; neither is packaged as a working backend.
- GPU measurements are sequential. CUDA owns the primary NVIDIA ALU and matrix result paths. OpenCL FP32 is a separately labeled compatibility measurement; the absent NVIDIA OpenCL half extension never implies absent FP16 hardware.
- No arbitrary SDK DLL glob is redistributed. Only a built worker plus audited, version-locked, licensed private runtime files can enter a binary package. Static MSVC/cudart removes a full development runtime dependency from host/CUDA. Windows driver DLLs stay in their system deployment. Clean-machine deployment remains unverified.
- User authorized unattended work and requested actual RTX5070Ti FP32/FP16/FP8 report, followed by shutdown. Shutdown is performed only after source, results, report and package manifests are saved; it is not part of build or validation scripts.
